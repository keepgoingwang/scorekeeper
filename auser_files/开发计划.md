# 棋牌计分小程序 — 开发计划 v1

> 基于 `prds/棋牌计分小程序 - 功能点需求文档.md` 梳理。
> 技术选型已确认：**MongoDB + WebSocket + 全栈分阶段（P0→P1→P2）**。
> 遵循 `.claude` 项目开发规范（前后端分离、分层架构、统一响应格式）。

---

## 一、技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | 微信小程序原生 | ES module + 自定义组件；按规范 pages/components/services/utils/behaviors 分层 |
| 后端 | Node.js + Express | Controller → Service → Model 分层 |
| 数据库 | MongoDB（Mongoose） | 嵌套文档结构友好，迭代快 |
| 实时通信 | WebSocket（ws） | 房间内积分/动态/结算状态机同步 |
| 鉴权 | JWT | wx.login → code2session → 自建 token |
| 二维码 | 后端 wxacode | scene 携带 roomNo，扫码进入即加入 |
| 部署 | 自建服务器 | HTTPS + WSS，配置小程序合法域名白名单 |

---

## 二、架构总览

```
前端  pages/components/services/utils/behaviors
        │  RESTful（request.util）        │  WebSocket（socket.util）
        ▼                                  ▼
后端  routes ─▶ controllers ─▶ services ─▶ models (Mongoose)
        │            │
        │            └─ middleware: auth(JWT+role) / validate(Joi) / error-handler
        └─ WebSocket 网关：按 roomNo 维护连接池
            广播 room:score / room:dynamic / room:settle / room:member / room:dissolved
```

**原则**（规范 separation）：前端只做 UI 与交互；业务逻辑、数据校验、权限校验在后端；前端不直连数据库、不存敏感数据。

---

## 三、核心数据模型（MongoDB）

- **User**：`openid, nickname, avatar, age, role, currentRoomId(ref), stats{games, winRate, maxScore, totalScore}, createdAt, updateTime, isDeleted`
- **Room**：`roomNo(unique), owner(ref), members[{userId, status, score, lastSubmit}], mode, state, skin, round, dynamics[], settleRound, createdAt, isDeleted`
- **Flow（流水）**：`roomId, round, type, from, to, amount, memo, createdAt`（软删除）
- **SettleRound**：`roomId, round, state(idle/input/verify), deadline, submissions[{userId, income, expense, submitted}], balance`
- **Record（战绩）**：`userId, roomId, roomNo, memberCount, score, result(win/even/lose), settledAt`

> 规范 database_rules：自动 createTime/updateTime、软删除 isDeleted、用户只能操作自己数据。

## 四、关键技术难点与方案

1. **用户房间唯一性**（全局规则 1）：`User.currentRoomId` 单一引用；create/join 在后端原子执行——校验旧房 → 退出旧房（房主则转移/解散）→ 加入新房。
2. **房主转移 / 解散**（§2.2 / §九）：房主退出时，有活跃成员则随机转房主，无则解散并推送 `room:dissolved`。
3. **自动结算状态机**（§6.1）：后端维护 `idle → input → verify → (balance | re-input)`；WS 同步 60s 倒计时；房主可 `endSettle`；超时未提交视为 0。
4. **收支平衡校验**（§6.2 Step4）：`Σ|income| == Σ|expense|`；不平衡则重置所有 `submitted`、重新推送、倒计时重置。
5. **实时广播**：WS 按 roomNo 分组连接池，事件 `room:score / room:dynamic / room:settle / room:member / room:dissolved`。
6. **牌桌筹码**（§4.4）：纯前端展示，依据 `member.score` 渲染堆叠 + 掉落动画；皮肤走 CSS 变量。
7. **房间号生成**：6 位，生成时查重保证唯一。
8. **分享二维码**：后端 wxacode，scene=roomNo；小程序 `onLoad(options.scene)` 解析后加入。

## 五、开发阶段（按 PRD 优先级 P0 → P1 → P2）

### 阶段 0：基建与联调通道（地基）
- 后端骨架：Express + Mongoose 连接 + 统一响应/错误中间件 + auth/validate 中间件 + WS 网关基础（`server/` 待建）
- 前端联调：`request.util` BASE、`socket.util` WS 通道（前端骨架已就绪）
- **登录闭环**：wx.login → /api/user/login → 下发 token → globalData
- AppID / 合法域名配置（测试号或正式号）

### 阶段 1（P0）：核心房间闭环（最小可玩）
目标：从建房到结算完整跑通。
- 创建/加入房间 + 房间唯一性 + 退出旧房二次确认（§2.2 / §2.3）
- 房间页六区域：头像区（≤5 滚动 + 退出灰态）、模式区、牌桌（皮肤+筹码）、动态区、底部操作（§4）
- 手动结算：支出 → 选收款人 → 输金额 → 转账（§7）
- 自动结算状态机：发起/输入/倒计时/校验/分配/不平衡重推（§6）
- 房间分享页：二维码 + 房间号 + 转发（§2.2 / §5）
- 操作菜单：查看流水 / 退出 / 解散 / 模式切换 / 皮肤（§4.6）
- 房主转移与边界（§九）
- 房间终局结算报告：排名 + 盈亏明细 + 建议转账方案（§8）

### 阶段 2（P1）：体验完善
- 流水记录页（§4.6）
- 我的页面 + 资料编辑（头像/昵称/年龄）（§3.1 / §3.2）
- 战绩查询：统计概览 + 场次明细 + 趋势图 + 排行榜（§3.3）
- 系统设置：皮肤 + 通知（声音/震动）（§3.4）
- 扫码页（§2.3）
- 房间设置弹窗（房主皮肤/模式切换）

### 阶段 3（P2）：辅助与打磨
- 帮助反馈 FAQ + 意见反馈（§3.5）
- 联系我们 + 版本/隐私协议（§3.6）
- 牌桌筹码动画打磨、皮肤切换预览
- 性能（规范 performance）：setData 合并、列表分页、图片懒加载、定时器/监听清理
- 异常处理全覆盖（§九 表）

## 八、风险与边界（PRD §九 异常处理）

逐一对接 §九 表，后端校验并返回统一错误码，前端按 `message` 提示：

| 场景 | 处理 |
| --- | --- |
| 创建/加入时已在其他房间 | 后端原子退出旧房 + 前端二次确认弹窗 |
| 房主退出且有活跃用户 | 随机转房主 |
| 房主退出且无活跃用户 | 解散房间 |
| 房间号不存在 | 提示「房间不存在或已解散」 |
| 自动结算收支不平衡 | 重置提交态、重新推送、倒计时重置 |
| 非房主操作房主功能 | 提示「只有房主可以执行此操作」 |
| 已退出用户操作 | 提示「您已退出房间，无法操作」 |
| 手动结算积分不足 | 提示「积分不足，当前可用积分：XX」 |
| 倒计时内房主退出 | 终止结算、数据作废 |
| 网络异常提交失败 | 保留输入、提示「提交失败，请重试」 |

## 九、与现有脚手架的衔接

前端骨架已就绪（11 页面 + 3 services + 5 utils + 1 behavior + empty-state 组件 + 配置文件）。本计划在此基础上填充业务逻辑；后端 `server/` 将按规范分层新建：

```
server/
  app.js                  Express 入口 + WS 网关
  package.json
  config/                 env.js, db.js
  middleware/             auth.js, validate.js, error.js
  controllers/            room / user / settlement
  services/               room / user / settlement
  models/                 user / room / flow / settle-round / record
  routes/                 index.js + 各资源路由
  utils/                  response.util.js, socket.util.js
  README.md
```
