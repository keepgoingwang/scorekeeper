# 棋牌计分小程序 — 功能点需求文档

## 一、全局规则



1. **用户房间唯一性**：每个用户同一时间只能存在于一个房间内

2. **底部Tab**：仅保留「首页」「我的」两个

3. **用户状态**：房间内用户分为「有效用户」（未退出，参与结算）和「已退出用户」（头像变灰，不参与后续任何结算）

4. **房主权限**：创建房间者为房主，拥有解散房间、切换结算模式、发起自动结算本局、强制结算等特权

5. **房主退出规则**：房主退出时，若房间还有活跃用户，随机挑选一位成为新房主；若无活跃用户，直接解散房间

## 二、首页



### 2\.1 页面布局



- 顶部：品牌Logo \+ 标语

- 中部：两个主功能区

    - **创建房间**（大号主按钮，薄荷绿）

    - **加入房间**（次按钮，支持扫码/输入房间号）

### 2\.2 创建房间



#### 流程



```Plain Text
用户点击「创建房间」
    ↓
系统检测用户当前是否在房间内
    ↓
【情况A】用户已在房间XXX中
    ↓
弹出确认弹窗：
"您当前在房间XXX中，开房会自动退出该房间，是否继续？"
    ├─ 继续
    │   ↓
    │   系统执行退出上一房间逻辑：
    │   ├─ 如果用户是上一房间房主：
    │   │   ↓
    │   │   检测上一房间是否还有活跃用户：
    │   │   ├─ 有活跃用户 → 随机挑选一位活跃用户成为新房主
    │   │   │              用户不再参与上一房间结算
    │   │   └─ 无活跃用户 → 直接解散上一房间
    │   └─ 如果用户不是房主：
    │       ↓
    │       用户直接退出上一房间，不再参与结算
```

```Plain Text
    │   ↓
    │   系统执行退出上一房间逻辑：
    │   ├─ 如果用户是上一房间房主：
    │   │   ↓
    │   │   检测上一房间是否还有活跃用户：
    │   │   ├─ 有活跃用户 → 随机挑选一位活跃用户成为新房主
    │   │   │              用户不再参与上一房间结算
    │   │   └─ 无活跃用户 → 直接解散上一房间
    │   └─ 如果用户不是房主：
    │       ↓
```

- 牌友排行榜（与该用户打过牌的所有人排名）

### 4\.2 顶部用户头像区



#### 布局规则

- **排列方式**：水平排列，一行最多 **5个用户头像**

- **头像结构**（从上到下）：

    - 第一层：用户头像（圆形，50px）

    - 第二层：用户昵称（最多6个字符，超出省略）

    - 第三层：实时积分（带颜色标识：绿色正数/红色负数/灰色零）

- **最右侧**：「\+ 邀请好友」按钮（固定位置，不参与滑动）

    

#### 用户状态

- **正常用户**：彩色头像，正常昵称颜色，积分实时更新

- **已退出用户**：

    - 头像变为灰度（去色处理）

    - 昵称显示为灰色

    - 积分显示为最终退出时的数值（不再变化）

    - **不参与后续任何积分分配和结算**

        

#### 溢出处理

- 若房间人数 \> 5，头像区**可横向滑动**（ScrollView）

- 滑动时显示边缘渐变遮罩，提示还有更多用户

- 邀请好友按钮始终固定在右侧，不参与滑动

    

### 4\.3 结算模式展示区（顶部用户区与牌桌之间）



#### 位置

- 位于顶部用户头像区下方，牌桌区域上方

- 高度约 **80\-100px**

- 背景使用浅灰色（\#F0F4F8）与主背景区分

    

#### 模式一：手动结算

- **显示内容**：

    - 标题：「手动结算模式」

    - 说明文字："点击底部「支出」按钮选择收款人进行精确支付"

    - 当前操作状态提示

- **房主专属**：右侧显示「⚙️ 设置」按钮，点击可切换为自动结算模式

    

#### 模式二：自动结算

- **显示内容**：

    - 标题：「自动结算模式」

    - 说明文字："房主发起结算后，所有用户将收到输入通知"

    - 当前局数：「第X局」

    - 输入状态提示（如："等待房主发起结算" / "输入中：3/5人已提交" / "剩余 45 秒"）

- **房主专属**：右侧显示「⚙️ 设置」按钮，点击可切换为手动结算模式

- **收支不匹配提示**：

    - 当所有玩家提交后，若总收入 ≠ 总支出（绝对值）

    - 显示红色警告："收支不平衡，差额：XX分，请重新输入"

    - 高亮显示可能存在问题的输入项

        

### 4\.4 牌桌区域（核心视觉区）



#### 面积要求

- **牌桌面积必须足够大**，占据屏幕中央主要区域

- 建议占屏幕高度的 **45%\-55%**

- 牌桌边缘距离屏幕左右边距 ≥ 16px

    

#### 牌桌形态

- **4人及以下**：正方形牌桌，玩家头像均匀分布在四边（牌桌外）

- **5人及以上**：圆形牌桌，玩家头像均匀分布在圆周（牌桌外）

- **第一圈最多8人**，若超过8人，第二圈头像在第一圈外侧

    

#### 筹码展示（关键视觉元素）

- **位置**：筹码放置在**牌桌桌面上**，而非头像旁

- **样式**：模拟真实赌场圆形筹码

    - 形状：圆形，带边框

    - 颜色：根据积分值变化（正积分=金色/绿色系，负积分=红色系）

    - 数量：积分绝对值越大，筹码堆越高（视觉堆叠效果）

    - 每个玩家的筹码堆位于其对应位置的牌桌边缘内侧

- **动态效果**：

    - 积分变化时，筹码有**堆叠/减少动画**

    - 新筹码从屏幕上方掉落至牌桌（300ms弹性动画）

        

#### 牌桌皮肤

- **切换入口**：仅保留在右上角「设置⚙️」按钮中

- **皮肤选项**：

    - 经典麻将（深绿 \#2D5A3D）

    - 德州之夜（深蓝黑 \#1A1A2E）

    - 休闲木桌（原木色 \#D4A373）

    - 清新薄荷（品牌色 \#4ECDC4）

- 屏幕中央**不显示皮肤切换按钮**

    

### 4\.5 房间动态区（牌桌下方）



#### 位置

- 牌桌区域与底部操作区之间

- 高度约 **60\-80px**

- 背景：半透明深色条（rgba\(0,0,0,0\.05\)）

    

#### 展示内容

- 滚动显示房间最新动态，类似消息 ticker

- **动态类型**：

    - 用户进入："🎉 张三 进入房间"

    - 用户退出："👋 李四 退出房间"

    - 积分支出："💸 张三 支出 50 积分 → 李四"

    - 积分收入："💰 王五 收入 30 积分 ← 赵六"

    - 模式切换："⚙️ 房主切换为自动结算模式"

    - 房主变更："👑 张三 成为新房主"

    - 房间解散："💥 房间已解散"

- **显示规则**：

    - 最多显示最近 **3条** 动态

    - 新动态从底部滑入，旧动态向上淡出

    - 支持手动上滑查看历史动态（展开为列表）

        

### 4\.6 底部操作区



#### 布局

- 固定在屏幕底部，高度约 **70px**

- 3个等宽按钮横向排列（自动模式时仅显示操作按钮）

- 按钮样式：圆角矩形（12px圆角），带图标\+文字

    

#### 普通用户底部按钮



**自动结算模式时**：

- 仅保留 **「⚙️ 操作」** 一个按钮

- 当房主发起「结算本局」后，系统向所有有效用户推送结算页面（覆盖当前界面），包含「收入」和「支出」两个输入框

    

**手动结算模式时**：

- 保留 **「💸 支出」** \+ **「⚙️ 操作」** 两个按钮

- 「支出」：点击后展示房间内所有参与结算用户（不含自己、不含已退出用户），选择收款人 → 输入金额 → 确认转账

    

#### 房主底部按钮



在普通用户基础上，**自动结算模式时额外显示「结算本局」按钮**：

- 按钮位置：底部操作区最左侧或最右侧（醒目位置）

- 按钮文案：「结算本局」或「发起第X局结算」

- 点击后触发自动结算流程

    

#### ⚙️ 操作按钮菜单



点击后从底部弹出操作菜单（Action Sheet）：



**普通用户菜单**：

- 📋 查看流水单 → 进入流水记录页

- 🚪 退出房间 → 二次确认 → 退出后头像变灰，不再参与结算

    

**房主额外菜单**：

- 📋 查看流水单

- 🚪 退出房间

- 💥 解散房间 → 二次确认 → 房间解散，所有用户返回首页

- ⚙️ 结算模式切换 → 手动/自动切换

- 🎨 牌桌皮肤设置 → 弹出皮肤选择弹窗

## 六、自动结算逻辑（核心）



### 6\.1 状态机



```Plain Text
┌─────────────┐
│   空闲状态   │  ← 正常游戏状态，等待房主发起
│  (可进行手动 │
│   结算操作)  │
└──────┬──────┘
       │ 房主点击「结算本局」
       ▼
┌─────────────┐
│  输入中状态  │  ← 向所有有效用户推送结算页面
│  (90秒倒计时)│    显示收入和支出两个输入框
│              │    用户输入后头像旁显示「已提交」绿点
└──────┬──────┘
       │ 倒计时结束 或 房主点击「结束输入」
       │ 或 所有人已提交
       ▼
┌─────────────┐
│   校验阶段   │  ← 系统校验：总收入绝对值 是否等于 总支出绝对值
│              │
└──────┬──────┘
       │
   ┌───┴───┐
   ▼       ▼
┌──────┐ ┌──────┐
│ 平衡  │ │ 不平衡│
│  ✓   │ │  ✗   │
└──┬───┘ └──┬───┘
   │        │
   ▼        ▼
┌────────┐ ┌────────────┐
│自动分配 │ │ 重新推送    │
│更新积分 │ │ 结算窗口    │
│动态通知 │ │ 所有人重新  │
│返回空闲 │ │ 输入（重置  │
│        │ │ 已提交状态） │
└────────┘ └────────────┘
```



### 6\.2 详细流程



**Step 1：房主发起**

1. 房主点击底部「结算本局」按钮

2. 系统记录当前局数（第X局）

3. 向房间内**所有有效用户**（未退出）推送结算页面

4. 结算页面为**全屏覆盖/模态弹窗**，包含：

    - 标题：「第X局结算」

    - 说明：「请输入本局收入或支出金额，不进不出可不填」

    - 输入框1：「收入金额」（数字键盘，正整数）

    - 输入框2：「支出金额」（数字键盘，正整数）

    - 「提交」按钮

    - 倒计时显示：「剩余 59 秒」

        

**Step 2：用户输入**

1. 用户收到结算页面后，在收入/支出中**至少填一项**（也可都不填，视为0）

2. 用户填写后点击「提交」

3. 提交后：

    - 用户本地结算页面关闭，返回房间页

    - 用户头像旁显示**小绿点**「已提交」

    - 顶部结算模式区显示提交进度：「3/5人已提交」

        

**Step 3：倒计时管理**

- 倒计时 **90秒**，所有用户同步

- 房主界面额外显示「结束输入」按钮，可提前结束倒计时

- 倒计时结束时：

    - 已提交用户：保留输入值

    - 未提交用户：自动视为**0分**（不进不出）

        

**Step 4：收支校验**

- 系统计算：总收入 = 所有用户收入之和

- 系统计算：总支出 = 所有用户支出之和

- **校验条件**：总收入绝对值 == 总支出绝对值

    - 即：赢家赢的总和 == 输家输的总和

        

**Step 5：校验结果处理**



**情况A：收支平衡**

1. 系统自动将收入/支出金额累加到各用户总积分

2. 更新顶部头像区积分显示

3. 更新牌桌筹码堆

4. 动态区显示：「第X局结算完成」

5. 房主的「结算本局」按钮变为「发起第X\+1局结算」

6. 所有用户返回空闲状态

    

**情况B：收支不平衡**

1. 系统计算差额：\|总收入 \- 总支出\|

2. **重新向所有有效用户推送结算页面**

3. **重置所有用户的「已提交」状态**（已提交的也需重新输入）

4. 结算页面显示红色警告：

    - 「收支不平衡，差额：XX分」

    - 「请重新输入本局收支」

5. 倒计时重新从90秒开始

6. 重复 Step 2\-5，直至收支平衡

    

### 6\.3 边界情况



- **用户输入负数**：输入框限制只能输入正整数，负数通过「收入/支出」字段区分

- **用户同时填收入和支出**：允许，但逻辑上视为净额（收入\-支出）

- **房主在输入中退出/解散**：立即终止当前结算，已提交数据作废，返回空闲状态

- **用户输入中退出房间**：已提交数据保留，退出后头像变灰，不再参与后续结算

- **倒计时内新用户加入**：新用户不参与当前局结算，从下一局开始

## 七、手动结算逻辑



### 7\.1 触发方式

- 用户点击底部「💸 支出」按钮

- 或点击牌桌旁其他用户头像（可选快捷方式）

    

### 7\.2 流程



1. 用户点击「支出」

2. 弹出用户选择列表：

    - 显示房间内所有**有效用户**（不含自己、不含已退出用户）

    - 每个用户显示头像\+昵称\+当前积分

3. 用户选择收款人

4. 弹出金额输入键盘：

    - 输入正整数金额

    - 显示付款人当前积分（仅参考，不做超额限制）

5. 用户点击「确认转账」

6. 系统执行：

    - 付款人积分减少相应金额

    - 收款人积分增加相应金额

    - 更新顶部头像区积分

    - 更新牌桌筹码堆

    - 动态区显示：「💸 张三 支出 50 积分 → 李四」

7. 返回房间页

    

### 7\.3 边界情况



- **付款人积分不足**：不做拦截，允许积分为负（初始积分均为0，若拦截则首笔转账无法发起；负分即欠分，终局结算判负并参与结清方案）

- **收款人已退出**：不显示在选择列表中

- **转账金额为0**：提示「请输入有效金额」

## 八、房间结算（终局）



### 8\.1 触发条件

- 房主点击操作菜单中的「房间结算」

- 或房主点击「解散房间」时触发最终结算

    

### 8\.2 结算逻辑

1. 读取每位有效用户的当前总积分（初始均为0）

2. 判断胜负：

    - 积分 \> 0：赢家（绿色标识）

    - 积分 = 0：保本（灰色标识）

    - 积分 \< 0：输家（红色标识）

3. 生成结算报告：

    - 排名列表（按积分从高到低）

    - 每人盈亏明细

    - 建议转账方案（最小化转账次数，谁给谁转多少结清）

4. 提供「分享战绩」按钮，生成战绩卡片

    

### 8\.3 结算后

- 房间状态变为「已结算」

- 所有用户可查看结算报告，但不可再进行积分操作

- 房主可解散房间，或重新开始（重置所有积分为0）

## 九、异常处理汇总



|场景|处理方式|
|---|---|
|创建房间时已在其他房间|弹出确认弹窗，选择继续（自动退出旧房）或返回|
|加入房间时已在其他房间|弹出确认弹窗，选择继续（自动退出旧房）或返回|
|房主退出且房间还有活跃用户|随机挑选一位活跃用户成为新房主|
|房主退出且房间无活跃用户|直接解散房间|
|房间号不存在|提示"房间不存在或已解散"|
|自动结算收支不平衡|重新推送结算窗口，所有人重新输入|
|非房主操作房主功能|提示"只有房主可以执行此操作"|
|已退出用户操作|提示"您已退出房间，无法操作"|
|手动结算付款人积分不足|不做拦截，直接转账，付款人积分可为负|
|倒计时内房主退出|终止当前结算，数据作废|
|网络异常提交失败|保留输入数据，提示"提交失败，请重试"|

## 十一、术语表



|术语|解释|
|---|---|
|开房|创建一个新的计分房间|
|房间号|6位数字，用于邀请他人加入|
|有效用户|未退出房间的用户，参与积分分配和结算|
|已退出用户|已退出房间的用户，头像变灰，不参与后续结算|
|房主|房间的创建者，拥有解散房间、切换模式、发起结算等权限|
|自动结算|房主发起结算后，所有用户在限时内输入收入/支出，系统自动校验平衡并分配|
|手动结算|支出方直接选择收款方进行精确转账|
|房间结算|所有牌局结束后的最终结算，判断胜负|
|筹码|牌桌上的圆形可视化元素，模拟真实赌场筹码|
|流水单|房间内所有积分变动的历史记录|
