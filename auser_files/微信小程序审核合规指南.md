# 微信小程序审核合规指南

> 基于两次审核被拒经验 + 微信官方《微信小程序平台运营规范》整理。
> 每次提审前对照本文档逐项自查，避免重复踩坑。

---

## 一、常见审核不合规点（按严重程度排序）

### 🔴 致命级（直接拒绝）

| # | 不合规点 | 说明 | 官方依据 |
|---|---------|------|---------|
| 1 | **强制登录 / 登录前置** | 用户打开小程序必须先登录才能看到任何内容/使用任何功能。微信要求：用户应能**先浏览、体验部分功能**，再自行决定是否登录 | 运营规范 §3.2 |
| 2 | **默认勾选隐私协议** | 隐私协议/用户协议的勾选框默认勾选，等于替用户做了同意决定 | 隐私合规要求 |
| 3 | **协议/隐私页为空或占位** | 点《用户协议》《隐私政策》进去是空白页或"敬请期待" | 运营规范 §3.8 |
| 4 | **收集信息超出必要范围** | 工具类小程序要求获取位置、手机号、通讯录等与功能无关的信息 | 《个人信息保护法》+ 微信隐私规范 |
| 5 | **未配置用户隐私保护指引** | 微信公众平台后台 → 设置 → 服务内容声明 → 用户隐私保护指引 未填写或未通过审核 | 隐私合规要求 |
| 6 | **诱导分享 / 诱导关注** | "分享得积分""关注领红包""转发解锁功能"等 | 运营规范 §3.5 |
| 7 | **iOS 虚拟支付违规** | iOS 端使用微信支付购买虚拟商品/会员/代币（苹果要求走 IAP） | 运营规范 §3.10 |
| 8 | **页面空白 / 功能不可用** | 审核员打开某页面白屏、报错、或核心功能不可用 | 运营规范 §2.1 |
| 9 | **类目不符** | 小程序实际功能与提交审核时所选类目不一致 | 运营规范 §1.2 |

### 🟡 高危级（大概率拒绝）

| # | 不合规点 | 说明 |
|---|---------|------|
| 10 | **无退出登录功能** | 用户登录后找不到退出/注销入口 |
| 11 | **强制授权** | 不授权某权限（如头像/位置）就不让使用基本功能 |
| 12 | **登录按钮文案不明确** | 按钮没有清楚表达"这是登录"，或用模糊文案诱导点击 |
| 13 | **个人信息收集未告知用途** | 收集头像/昵称/年龄等未提前说明用于什么 |
| 14 | **UGC 无内容安全机制** | 用户可输入昵称/反馈等文本，但无敏感词过滤或举报机制 |
| 15 | **名称/图标/描述含敏感词或侵权** | 含"微信""官方"等字样，或使用他人商标 |

### 🟢 中危级（可能拒绝 / 影响体验）

| # | 不合规点 | 说明 |
|---|---------|------|
| 16 | **自定义导航栏与系统导航栏重复** | 页面设了 `navigationStyle: custom` 但又画了自己的返回按钮，或非 custom 页面画了多余返回按钮 |
| 17 | **弹窗 confirmText 超 4 字** | `wx.showModal` 的 confirmText/cancelText 超过 4 个汉字会静默失败 |
| 18 | **未适配刘海屏/安全区** | 内容被状态栏/底部安全区遮挡 |
| 19 | **分享功能缺失或异常** | 配置了分享但分享卡片无标题/图片，或分享后打开报错 |

## 二、当前项目逐项检查结果

### 🔴 必须修复

#### 1. 强制登录（本次被拒直接原因）

**现状**：`pages/home/home.js` 的 `onShow` 中：
```js
if (!getApp().globalData.token) {
  wx.redirectTo({ url: '/pages/login/login' });
  return;
}
```
用户打开小程序 → 首页 `onShow` → 无 token → 直接跳登录页。**用户零体验就被强制登录**。

**修复方向**：
- 首页改为**游客可浏览**模式：未登录时展示品牌介绍、使用指南、功能预览等内容，登录按钮作为"可选操作"而非"强制拦截"
- 只有**需要登录才能用的操作**（创建房间、加入房间、查看战绩等）才在点击时检查登录态，未登录则引导登录
- `app.json` 的 tabBar 首页不应强制跳登录

#### 2. 无退出登录功能

**现状**：全局搜索 `logout`/`退出登录`/`removeStorage.*token` 在 pages 目录下**零结果**。用户登录后无法退出账号。

**修复方向**：
- 在「我的」页面或「系统设置」页面底部加"退出登录"按钮
- 点击后清除 token + globalData + storage，跳回首页（游客态）

### 🟡 建议修复

#### 3. 帮助页/联系页/设置页的自定义返回按钮

**现状**：`help.wxml`、`contact.wxml`、`settings.wxml` 都有 `<button class="xxx__back" bindtap="onBack">← 返回</button>`，但这些页面的 json **没有** `navigationStyle: custom`，所以系统导航栏已经有一个返回箭头，页面里又画了一个 = 双重返回。

**修复方向**：和流水页一样，删掉自定义返回按钮，交给系统导航栏。

#### 4. request.util 401 处理对游客不友好

**现状**：`utils/request.util.js` 中 401 响应会 `reLaunch` 到登录页。如果游客模式下某些页面误调了需要 token 的接口，会被强制跳走。

**修复方向**：401 时先判断当前是否在游客态，如果是则不跳登录、只静默失败或 toast 提示。

### 🟢 已合规（无需改动）

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 隐私协议默认未勾选 | ✅ | `agreed: false`，用户必须主动勾选 |
| 未勾选时登录拦截 | ✅ | 弹窗提示 + "同意协议"按钮，语义闭环 |
| 协议页有实质内容 | ✅ | 71 行用户协议 + 75 行隐私政策，有更新日期 |
| 无敏感 API 调用 | ✅ | 无 getLocation/getPhoneNumber/chooseAddress 等 |
| 无诱导分享/关注 | ✅ | 无"分享得积分"等逻辑 |
| 无虚拟支付 | ✅ | 无 wx.requestPayment / 充值 / 会员购买 |
| 登录按钮文案明确 | ✅ | "微信一键登录"，意图清晰 |
| 无强制授权 | ✅ | 一键登录不弹任何授权弹窗 |

## 三、提审前自查清单

每次提交审核前，逐项打勾：

- [ ] 用户打开小程序**不登录也能看到内容**（首页/功能介绍/使用指南等）
- [ ] 登录是**用户主动选择**，不是被迫
- [ ] 隐私协议勾选框**默认未勾选**
- [ ] 未勾选时点登录有**明确拦截提示**
- [ ] 《用户协议》《隐私政策》页面**有实质内容**、可正常打开
- [ ] 微信公众平台后台**用户隐私保护指引已填写并通过**
- [ ] 有**退出登录**入口
- [ ] 无诱导分享/关注逻辑
- [ ] 无 iOS 虚拟支付
- [ ] 所有页面**无白屏/报错**
- [ ] 无多余/重复的返回按钮
- [ ] 小程序名称/图标/描述**无敏感词**
- [ ] 所选**类目与实际功能匹配**
- [ ] UGC 输入（昵称/反馈）有**基本的内容安全处理**（至少后端校验长度/格式）
- [ ] `wx.showModal` 的 confirmText/cancelText **≤ 4 个汉字**

## 四、本次审核被拒原因与修复优先级

| 优先级 | 问题 | 修复工作量 | 说明 |
|--------|------|-----------|------|
| **P0** | 强制登录 → 改为游客可浏览 | 中 | 首页去掉 onShow 强制跳登录；未登录时展示品牌+指南+功能预览；创建/加入房间等操作点击时才检查登录 |
| **P0** | 无退出登录 | 小 | 「我的」或「设置」页加退出按钮 |
| **P1** | 帮助/联系/设置页双重返回 | 小 | 删自定义返回按钮 |
| **P1** | 401 对游客不友好 | 小 | request.util 401 时判断游客态 |
| **P2** | 后台隐私保护指引 | 配置 | 去微信公众平台填写并提交 |
