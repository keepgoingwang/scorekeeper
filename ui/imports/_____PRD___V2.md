## 二、产品概述

### 2.1 产品背景
线下打牌时，计分算账往往依赖纸笔或心算，容易出错、效率低、体验差。本小程序旨在提供一套**可视化、智能化、社交化**的计分工具，让计分过程像游戏一样轻松愉快。

### 2.2 产品目标
- 支持快速开房、扫码入房，降低使用门槛
- 提供两种计分模式（自动/手动），适配不同打牌习惯
- 以牌桌可视化布局替代传统列表，增强沉浸感
- 房间结算时自动判断胜负，无需人工计算

### 2.3 用户画像
- **主要用户**：20-50岁，经常线下打牌（麻将、扑克等）的社交群体
- **使用场景**：茶馆、棋牌室、家庭聚会等线下场景
- **核心痛点**：计分繁琐、算账易错、缺乏战绩记录

### 4.2 功能说明

#### 4.2.1 创建房间
- **入口**：首页大号主按钮「🎲 创建房间」
- **流程**：
  1. 点击按钮 → 立即创建房间（无需选择人数/模式）
  2. 自动进入房间页
  3. **进入房间后立即弹出房间二维码弹窗**，供用户分享邀请好友
  4. 二维码弹窗可关闭，关闭后留在房间页
- **房间号**：6位随机数字，显示在房间页顶部

#### 4.2.2 加入房间
- **入口**：首页次按钮「📷 加入房间」
- **方式**：
  - 方式一：点击唤起相机扫码
  - 方式二：点击弹出输入框，输入6位房间号
- **校验**：
  - 房间号不存在 → 提示"房间不存在或已解散"
  - 用户已在其他房间 → 提示"您当前已在房间XXX中，请先退出"
  - 加入成功 → 进入房间页

#### 4.2.3 当前所在房间卡片
- **显示条件**：用户当前在某个房间内（未退出）
- **隐藏条件**：用户不在任何房间中
- **内容**：
  - 房间号
  - 当前成员数
  - 房间状态（进行中/已结算）
  - 快捷按钮「点击返回房间」→ 直接进入房间页
- **规则**：用户**同一时间只能存在于一个房间**

### 5.2 顶部用户头像区

#### 5.2.1 布局规则
- **排列方式**：水平排列，一行最多 **5个用户头像**
- **头像结构**（从上到下）：
  - 第一层：用户头像（圆形，50px）
  - 第二层：用户昵称（最多6个字符，超出省略）
  - 第三层：实时积分（带颜色标识：绿色正数/红色负数/灰色零）
- **最右侧**：「+ 邀请好友」按钮（固定位置）

#### 5.2.2 用户状态
- **正常用户**：彩色头像，正常昵称颜色，积分实时更新
- **已退出用户**：
  - 头像变为灰度（去色处理）
  - 昵称显示为灰色
  - 积分显示为最终退出时的数值（不再变化）
  - **不参与后续任何积分分配和结算**

#### 5.2.3 溢出处理
- 若房间人数 > 5，头像区**可横向滑动**（ScrollView）
- 滑动时显示边缘渐变遮罩，提示还有更多用户
- 邀请好友按钮始终固定在右侧，不参与滑动

### 5.3 结算模式展示区（顶部用户区与牌桌之间）

#### 5.3.1 位置
- 位于顶部用户头像区下方，牌桌区域上方
- 高度约 **80-100px**
- 背景使用浅灰色（#F0F4F8）与主背景区分

#### 5.3.2 模式一：手动结算
- **显示内容**：
  - 标题：「手动结算模式」
  - 说明文字："点击支出方头像，再点击收入方头像进行精确支付"
  - 当前操作状态提示（如："请选择付款人" → "请选择收款人"）
- **房主专属**：右侧显示「⚙️ 设置」按钮，点击可切换为自动结算模式

#### 5.3.3 模式二：自动结算
- **显示内容**：
  - 标题：「自动结算模式」
  - 说明文字："请输入本局收入或支出，系统将自动计算分配"
  - 输入状态提示（如："等待所有玩家输入... 3/5人已提交"）
- **房主专属**：右侧显示「⚙️ 设置」按钮，点击可切换为手动结算模式
- **收支不匹配提示**：
  - 当所有玩家提交后，若总收入 ≠ 总支出（绝对值）
  - 显示红色警告："收支不平衡，差额：XX分，请检查输入"
  - 高亮显示可能存在问题的输入项

### 5.4 牌桌区域（核心视觉区）

#### 5.4.1 面积要求
- **牌桌面积必须足够大**，占据屏幕中央主要区域
- 建议占屏幕高度的 **45%-55%**
- 牌桌边缘距离屏幕左右边距 ≥ 16px

#### 5.4.2 牌桌形态
- **4人及以下**：正方形牌桌，玩家头像均匀分布在四边（牌桌外）
- **5人及以上**：圆形牌桌，玩家头像均匀分布在圆周（牌桌外）
- **第一圈最多8人**，若超过8人，第二圈头像在第一圈外侧

#### 5.4.3 筹码展示（关键视觉元素）
- **位置**：筹码放置在**牌桌桌面上**，而非头像旁
- **样式**：模拟真实赌场圆形筹码
  - 形状：圆形，带边框
  - 颜色：根据积分值变化（正积分=金色/绿色系，负积分=红色系）
  - 数量：积分绝对值越大，筹码堆越高（视觉堆叠效果）
  - 每个玩家的筹码堆位于其对应位置的牌桌边缘内侧
- **动态效果**：
  - 积分变化时，筹码有**堆叠/减少动画**
  - 新筹码从屏幕上方掉落至牌桌（300ms弹性动画）

#### 5.4.4 牌桌皮肤
- **切换入口**：仅保留在右上角「设置⚙️」按钮中
- **皮肤选项**：
  - 经典麻将（深绿 #2D5A3D）
  - 德州之夜（深蓝黑 #1A1A2E）
  - 休闲木桌（原木色 #D4A373）
  - 清新薄荷（品牌色 #4ECDC4）
- 屏幕中央**不显示皮肤切换按钮**

### 5.5 房间动态区（牌桌下方）

#### 5.5.1 位置
- 牌桌区域与底部操作区之间
- 高度约 **60-80px**
- 背景：半透明深色条（rgba(0,0,0,0.05)）

#### 5.5.2 展示内容
- 滚动显示房间最新动态，类似消息 ticker
- **动态类型**：
  - 用户进入："🎉 张三 进入房间"
  - 用户退出："👋 李四 退出房间"
  - 积分支出："💸 张三 支出 50 积分 → 李四"
  - 积分收入："💰 王五 收入 30 积分 ← 赵六"
  - 模式切换："⚙️ 房主切换为自动结算模式"
- **显示规则**：
  - 最多显示最近 **3条** 动态
  - 新动态从底部滑入，旧动态向上淡出
  - 支持手动上滑查看历史动态（展开为列表）

### 5.6 底部操作区（3个Banner）

#### 5.6.1 布局
- 固定在屏幕底部，高度约 **70px**
- 3个等宽按钮横向排列
- 按钮样式：圆角矩形（12px圆角），带图标+文字

#### 5.6.2 按钮配置（根据结算模式动态变化）

**手动结算模式时**：
| 按钮 | 显示 | 功能 |
|------|------|------|
| 💸 支出 | 显示 | 点击后展示房间内所有参与结算用户（不含自己），选择收款人 |
| （收入按钮隐藏） | 隐藏 | 手动模式下不需要收入按钮 |
| ⚙️ 操作 | 显示 | 展开操作菜单 |

**自动结算模式时**：
| 按钮 | 显示 | 功能 |
|------|------|------|
| 💰 收入 | 显示 | 点击输入本局收入金额 |
| 💸 支出 | 显示 | 点击输入本局支出金额 |
| ⚙️ 操作 | 显示 | 展开操作菜单 |

#### 5.6.3 收支按钮交互

**💰 收入按钮（自动模式）**：
- 点击 → 弹出数字键盘输入框
- 输入正数金额
- 提交后显示"已提交"状态，按钮变为不可点击（灰色）
- 所有玩家提交后，系统进行收支平衡校验

**💸 支出按钮（自动模式）**：
- 点击 → 弹出数字键盘输入框
- 输入正数金额（表示支出）
- 提交后显示"已提交"状态

**💸 支出按钮（手动模式）**：
- 点击 → 弹出用户选择列表
- 列表显示所有**参与结算的用户**（不含自己、不含已退出用户）
- 选择收款人 → 弹出金额输入 → 确认转账
- 转账成功后，动态区显示转账记录

#### 5.6.4 ⚙️ 操作按钮

点击后从底部弹出操作菜单（Action Sheet）：

**普通用户菜单**：
- 📋 查看流水单 → 进入流水记录页
- 🚪 退出房间 → 二次确认 → 退出后头像变灰

**房主额外菜单**：
- 📋 查看流水单
- 🚪 退出房间
- 💥 解散房间 → 二次确认 → 房间解散，所有用户返回首页
- ⚙️ 结算模式切换 → 手动/自动切换
- 🎨 牌桌皮肤设置 → 弹出皮肤选择弹窗

## 六、结算流程详解

### 6.1 手动结算流程

```
1. 用户点击底部「💸 支出」按钮
   ↓
2. 弹出用户选择列表（房间内所有有效用户，不含自己）
   ↓
3. 用户选择收款人（如：李四）
   ↓
4. 弹出金额输入键盘，输入转账金额
   ↓
5. 点击确认
   ↓
6. 系统执行：
   - 付款人积分减少
   - 收款人积分增加
   - 更新顶部头像区积分显示
   - 更新牌桌筹码堆
   - 动态区显示："💸 张三 支出 50 积分 → 李四"
   ↓
7. 返回房间页
```

### 6.2 自动结算流程

```
1. 每局结束后，房主或任意用户点击「💰 收入」或「💸 支出」
   ↓
2. 用户输入本局收入或支出金额（二选一，不进不出可不操作）
   ↓
3. 提交后，按钮显示"已提交"，等待其他玩家
   ↓
4. 当所有玩家都提交后（或房主强制结算）
   ↓
5. 系统校验：总收入绝对值 是否等于 总支出绝对值
   ↓
6. 【校验通过】→ 自动分配积分，更新所有用户积分
   ↓
7. 【校验失败】→ 弹出红色警告：
   "收支不平衡，差额：XX分"
   高亮问题输入项，要求重新输入
   ↓
8. 重新输入后再次校验，直至通过
```

### 6.3 房间结算（终局）

**触发条件**：房主点击操作菜单中的「房间结算」

**结算逻辑**：
1. 系统读取每位玩家的当前总积分（每人初始积分为0）
2. 判断胜负：
   - 积分 > 0：赢家（绿色标识）
   - 积分 = 0：保本（灰色标识）
   - 积分 < 0：输家（红色标识）
3. 生成结算报告：
   - 排名列表（按积分从高到低）
   - 每人盈亏明细
   - 建议转账方案（最小化转账次数）
4. 提供「分享战绩」按钮

## 八、视觉设计规范

### 8.1 设计理念
**"轻松、愉悦、社交"** —— 让计分过程像游戏一样有趣，降低算账的焦虑感。

### 8.2 色彩体系

| 用途 | 色值 | 说明 |
|------|------|------|
| **主色调** | `#4ECDC4`（薄荷绿） | 品牌主色，用于主按钮、选中状态、重要标识 |
| **辅助色** | `#45B7D1`（天空蓝） | 次要按钮、链接、信息提示 |
| **强调色** | `#FFD93D`（明黄色） | 筹码、赢家标识、重要数据高亮 |
| **成功色** | `#6BCB77`（草绿色） | 正向积分、成功提示 |
| **警告色** | `#FF9F45`（橙色） | 中等提示、待确认状态 |
| **危险色** | `#FF6B6B`（珊瑚红） | 负向积分、错误提示、输家标识 |

## 九、交互规范

### 9.1 页面转场

## 十、异常处理

### 10.1 网络异常
- 页面加载失败：网络异常插画 + "网络开小差了，点击重试"
- 结算提交失败：保留输入数据，提示"提交失败，请重试"

### 10.2 业务异常
- 房间号不存在："房间不存在或已解散"
- 用户已在其他房间："您当前已在房间XXX中，请先退出"
- 收支不平衡："收支不平衡，差额：XX分，请检查输入"
- 非房主操作："只有房主可以执行此操作"

### 10.3 权限异常
- 未登录用户：引导登录/注册
- 非房间成员："您不是该房间成员"
- 已退出用户操作："您已退出房间，无法操作"

## 十二、术语表
